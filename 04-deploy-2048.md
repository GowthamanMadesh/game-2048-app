# Deploy Game 2048

This guide explains how to deploy the **2048 game application** on Amazon EKS using **AWS Fargate** and expose it through an **AWS Application Load Balancer (ALB)**.

---

## Cluster Details

| Configuration         | Value                         |
| --------------------- | ----------------------------- |
| Cluster Name          | `demo-eks-cluster`            |
| AWS Region            | `ap-south-1`                  |
| Application Namespace | `game-2048`                   |
| Compute               | AWS Fargate                   |
| Load Balancer         | AWS Application Load Balancer |
| Ingress Class         | `alb`                         |

---

# Step 1: Create Fargate Profile

Create a Fargate profile for the `game-2048` namespace:

```powershell
eksctl create fargateprofile --cluster demo-eks-cluster --region ap-south-1 --name alb-sample-app --namespace game-2048
```

This ensures that pods deployed in the `game-2048` namespace are scheduled on **AWS Fargate**.

> **Note:** The namespace is used by the Fargate profile selector. The profile must exist before application pods are scheduled.

---

# Step 2: Verify Fargate Profile

List the Fargate profiles associated with the EKS cluster:

```powershell
eksctl get fargateprofile --cluster demo-eks-cluster --region ap-south-1
```

Example output:

```text
NAME              CLUSTER          STATUS
alb-sample-app    demo-eks-cluster ACTIVE
```

---

# Step 3: Deploy Game 2048 Application

Deploy the Game 2048 application using the AWS Load Balancer Controller example manifest:

```powershell
kubectl apply -f https://raw.githubusercontent.com/kubernetes-sigs/aws-load-balancer-controller/v2.11.0/docs/examples/2048/2048_full.yaml
```

The Kubernetes manifest creates the following resources:

* Namespace
* Deployment
* Service
* Ingress

The Ingress resource is configured to use the AWS Load Balancer Controller.

---

# Step 4: Verify Namespace

Check that the `game-2048` namespace has been created:

```powershell
kubectl get namespace
```

You should see:

```text
game-2048
```

You can also directly check the namespace:

```powershell
kubectl get namespace game-2048
```

---

# Step 5: Verify Pods

Check the Game 2048 pods:

```powershell
kubectl get pods -n game-2048
```

Example output:

```text
NAME                           READY   STATUS    RESTARTS   AGE
deployment-2048-xxxxxxxxxx    1/1     Running   0          1m
```

> The pod name will be different in your cluster.

If the pod is stuck in `Pending`, check the pod events:

```powershell
kubectl describe pod -n game-2048 <POD_NAME>
```

---

# Step 6: Verify Service

Check the Kubernetes service:

```powershell
kubectl get svc -n game-2048
```

Example output:

```text
NAME           TYPE        CLUSTER-IP      EXTERNAL-IP   PORT(S)
service-2048   ClusterIP   10.xxx.xxx.xxx  <none>        80/TCP
```

The service provides internal connectivity between the ALB and the Game 2048 pods.

---

# Step 7: Verify Ingress

Check the Kubernetes Ingress:

```powershell
kubectl get ingress -n game-2048
```

Example output:

```text
NAME           CLASS   HOSTS   ADDRESS
ingress-2048   alb     *       k8s-game2048-xxxxxxxx.ap-south-1.elb.amazonaws.com
```

The `ADDRESS` field may initially be empty.

> **Note:** It can take a few minutes for the AWS Load Balancer Controller to provision the Application Load Balancer.

---

# Step 8: Watch Ingress Status

To continuously monitor the Ingress until the ALB address appears:

```powershell
kubectl get ingress -n game-2048 -w
```

Press **`Ctrl + C`** to stop watching.

Once provisioning is complete, the output should contain an ALB DNS name similar to:

```text
k8s-game2048-xxxxxxxx.ap-south-1.elb.amazonaws.com
```

---

# Step 9: Check Ingress Details

For additional information about the ALB provisioning process:

```powershell
kubectl describe ingress ingress-2048 -n game-2048
```

Check the **Events** section for messages from the AWS Load Balancer Controller.

---

# Step 10: Verify All Application Resources

Run:

```powershell
kubectl get all -n game-2048
```

This displays the application's:

* Pods
* Services
* Deployments
* ReplicaSets

Check the Ingress separately:

```powershell
kubectl get ingress -n game-2048
```

---

# Step 11: Access the Game 2048 Application

Get the ALB DNS name:

```powershell
kubectl get ingress -n game-2048
```

Copy the value under the **ADDRESS** column.

Example:

```text
k8s-game2048-xxxxxxxx.ap-south-1.elb.amazonaws.com
```

Open the ALB address in your web browser:

```text
http://k8s-game2048-xxxxxxxx.ap-south-1.elb.amazonaws.com
```

The **Game 2048 application** should now be accessible through the AWS Application Load Balancer.

---

# Architecture

The application traffic flows through the following architecture:

```text
                    Internet
                       |
                       v
            AWS Application Load Balancer
                       |
                       v
                Kubernetes Ingress
                       |
                       v
                Kubernetes Service
                       |
                       v
              Game 2048 Pods
                       |
                       v
                  AWS Fargate
                       |
                       v
                  Amazon EKS
```

# Verification Checklist

Before considering the deployment complete, verify:

* [ ] `game-2048` namespace exists.
* [ ] Fargate profile `alb-sample-app` is active.
* [ ] Game 2048 pods are `Running`.
* [ ] Kubernetes service is available.
* [ ] Ingress has `CLASS` set to `alb`.
* [ ] Ingress receives an AWS ALB DNS address.
* [ ] Application is accessible through the ALB DNS name.
